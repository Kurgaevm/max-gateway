# MAX Шлюз

Свой шлюз для мессенджера MAX: вход по номеру телефона, как обычный пользователь, и полноценный API для отправки и приёма сообщений. Аналог Green-API / WAHA, но для MAX и на своём сервере.

Клиенты переписываются с вашим салоном как с живым человеком: сообщения приходят с личного аккаунта, а не от бота. Писать можно первому, без ограничений.

> **Важно.** Шлюз работает через внутренний API MAX (неофициальный). Протокол может измениться без предупреждения, а аккаунт могут ограничить за автоматизацию. Используйте на свой риск, не ставьте на единственный рабочий аккаунт без запасного канала связи.

## Возможности

- Вход по телефону и коду из SMS (и облачному паролю 2FA, если задан)
- Веб-интерфейс: вход, статус, тестовая отправка, журнал входящих
- Отправка сообщений через REST API: `POST /sendText`
- Приём входящих: пересылка вебхуком на ваш URL (формат совместим с Green-API)
- Сессия сохраняется на диске: перезапуск контейнера не требует повторного входа
- Автоматическое переподключение при обрыве связи

## Требования

- Сервер (VPS) от 1 ГБ RAM, любой регион
- Docker и Docker Compose v2
- Номер телефона с установленным MAX (или без: аккаунт создастся при первом входе)

## Установка

### Вариант 1: одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/Kurgaevm/max-gateway/main/install.sh | bash
```

### Вариант 2: вручную

```bash
git clone https://github.com/Kurgaevm/max-gateway.git ~/max-gateway
cd ~/max-gateway
cp .env.example .env
# впишите в .env свой ключ: openssl rand -hex 24
docker compose up -d --build
```

После установки откройте веб-интерфейс: `http://127.0.0.1:8090/` и введите API-ключ из `.env` (строка `MAXGW_API_KEY`).

## Первый вход

1. В веб-интерфейсе введите телефон аккаунта MAX и нажмите «Запросить код»
2. Введите код из SMS
3. Если аккаунт защищён облачным паролем (2FA) — введите его
4. Статус сменится на «подключено». Готово, повторный вход не нужен

При первом входе с нового номера аккаунт MAX создастся автоматически с именем из `.env` (`MAXGW_REG_FIRST`, `MAXGW_REG_LAST`).

## Подключение к n8n

### Входящие сообщения

В `.env` укажите адрес вебхука:

```
MAXGW_WEBHOOK_URL=https://ваш-n8n/webhook/max_incoming
```

и перезапустите: `docker compose restart`. Каждое входящее сообщение уйдёт POST-запросом:

```json
{
  "typeWebhook": "incomingMessageReceived",
  "instanceData": { "idInstance": 1, "wid": "+79990000000", "typeInstance": "max" },
  "timestamp": 1789743931,
  "idMessage": "117292658309101931",
  "senderData": {
    "chatId": "373749415",
    "senderId": "373749415",
    "senderName": "Иван"
  },
  "messageData": {
    "typeMessage": "textMessage",
    "textMessageData": { "textMessage": "Привет, хочу записаться" }
  }
}
```

В n8n это принимает нода Webhook (POST, путь `max_incoming`).

### Исходящие сообщения

Нода HTTP Request в n8n:

- Method: `POST`
- URL: `http://maxgateway:8090/sendText` (если n8n и шлюз в одной сети Docker) или `http://IP-СЕРВЕРА:8090/sendText`
- Headers: `X-Api-Key` = ключ из `.env`
- Body (JSON):

```json
{ "phone": "+79990000000", "message": "Ваши ноготки ждут в пятницу в 15:00!" }
```

Вместо `phone` можно передать `chat_id` (число) из входящего вебхука.

## Справка API

Все запросы требуют заголовок `X-Api-Key`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/status` | Статус сессии и соединения |
| POST | `/login` | `{ "phone": "+7..." }` — начать вход (или перезапуск сессии) |
| POST | `/code` | `{ "code": "123456" }` — код из SMS |
| POST | `/password` | `{ "password": "..." }` — облачный пароль 2FA |
| POST | `/sendText` | `{ "phone": "+7...", "message": "..." }` или `{ "chat_id": 123, "message": "..." }` |
| POST | `/reset` | Сбросить сессию (потребуется новый вход по SMS) |
| GET | `/recent` | Последние 25 входящих сообщений |

## Безопасность

- По умолчанию шлюз слушает только `127.0.0.1:8090` — снаружи не виден
- Для доступа снаружи поставьте реверс-прокси (Caddy, Nginx) с HTTPS и не публикуйте порт напрямую
- API-ключ генерируется при установке, хранится в `.env`, не передавайте его третьим лицам
- Файлы сессии лежат в `./data` — не публикуйте эту папку и делайте бэкап

## Обновление

```bash
cd ~/max-gateway
docker compose down
git pull
docker compose up -d --build
```

Сессия в `./data` сохранится, повторный вход не нужен.

## Ограничения текущей версии

- Один аккаунт MAX на установку (для салона этого достаточно)
- Только текстовые сообщения; вложения во входящих отображаются как метаданные
- Вход по SMS-коду; QR-входа нет
