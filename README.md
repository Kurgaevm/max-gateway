# Мессенджер-шлюз (MAX + Telegram)

Свой шлюз для мессенджеров MAX и Telegram: вход по номеру телефона, как обычный пользователь, и полноценный API для отправки и приёма сообщений. Аналог Green-API / WAHA, но на своём сервере и без чужих облаков.

Клиенты переписываются с вашим салоном как с живым человеком: сообщения приходят с личного аккаунта, а не от бота. Писать можно первому, без ограничений.

> **Важно.** Шлюз работает через внутренний API MAX (неофициальный). Протокол может измениться без предупреждения, а аккаунт могут ограничить за автоматизацию. Для Telegram используется официальный протокол MTProto (библиотека Telethon). Используйте на свой риск, не ставьте на единственный рабочий аккаунт без запасного канала связи.

## Возможности

- Несколько аккаунтов на одной установке: инстансы с отдельными сессиями, ключами и вебхуками
- Инстансы двух типов: **max** и **telegram**, общий REST API и общий формат вебхуков
- Вход по телефону и коду (SMS для MAX, код в приложении для Telegram) и облачному паролю 2FA
- Вход в Telegram по QR-коду, как в WhatsApp Web: телефон -> Настройки -> Устройства
- Веб-интерфейс: аккаунты, вход (в т.ч. QR), статус, тестовая отправка, журнал входящих
- Отправка сообщений через REST API: POST /i/{инстанс}/sendText
- Приём входящих: пересылка вебхуком на ваш URL (формат совместим с Green-API)
- Скачивание вложений Telegram: GET /i/{инстанс}/getFile
- Голосовые сообщения: скачивание и расшифровка в текст через OpenAI-совместимый STT
- Сессии сохраняются на диске: перезапуск контейнера не требует повторного входа
- Автоматическое переподключение при обрыве связи

## Требования

- Сервер (VPS) от 1 ГБ RAM, любой регион
- Docker и Docker Compose v2
- Номер телефона с установленным MAX (или без: аккаунт создастся при первом входе)
- Для Telegram-инстансов: api_id/api_hash своего приложения с my.telegram.org (бесплатно, один раз на все аккаунты)

## Установка

### Вариант 1: одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/Kurgaevm/max-gateway/main/install.sh | bash
```

### Вариант 2: вручную

```bash
git clone https://github.com/Kurgaevm/max-gateway.git ~/max-gateway
cd ~/max-gateway
cp .env.example .env
# впишите в .env свой ключ: openssl rand -hex 24
docker compose up -d --build
```

После установки откройте веб-интерфейс: `http://127.0.0.1:8090/` и введите API-ключ из `.env` (строка `MAXGW_API_KEY`).

### Состав каналов: ставить ли VK

Каналы MAX и Telegram — лёгкие python-пакеты, ставятся всегда. Канал **VK** (личные страницы ВКонтакте) требует браузер в образе (playwright + chromium, ~500 МБ), поэтому он опционален:

- установщик спросит при установке «Включить канал VK?» — по умолчанию нет;
- неинтерактивно: `INSTALL_VK=1 curl -fsSL https://raw.githubusercontent.com/Kurgaevm/max-gateway/main/install.sh | bash`;
- вручную: впишите `INSTALL_VK=0` в `.env` и выполните `docker compose up -d --build`.

В сборке без VK инстансы ВК недоступны: создание вернёт 503, в веб-интерфейсе тип ВК не показывается. Передумали — уберите `INSTALL_VK=0` из `.env` и пересоберите.

### Домен и HTTPS (если на сервере стоит selfhost-ai)

Установщик умеет сразу привязать домен — спросит при установке, или передайте переменной:

```bash
MAXGW_DOMAIN=max.example.ru curl -fsSL https://raw.githubusercontent.com/Kurgaevm/max-gateway/main/install.sh | bash
# каталог стека нестандартный — добавь SELFHOST_DIR=/путь/к/selfhost-ai
```

Установщик сам: подключит шлюз к docker-сети стека (`localai_default`), допишет блок в `caddy-addon/tls-snippet.conf` стека (файл в `.gitignore` стека, обновления `make update` его не затирают) и перезагрузит Caddy. Останется только DNS: A-запись `домен -> IP сервера`, сертификат Let's Encrypt Caddy выпустит сам.

Вход: `https://max.example.ru`, тот же API-ключ. Сменить домен позже — отредактируй блок в `caddy-addon/tls-snippet.conf` и выполни `docker exec caddy caddy reload --config /etc/caddy/Caddyfile`.

## Первый вход

Веб-интерфейс закрыт basic auth: логин `admin` (меняется через `MAXGW_HTTP_USER` в `.env`), пароль генерируется автоматически при первом запуске. Установщик показывает оба в финальном отчёте; посмотреть позже:

```bash
docker exec maxgateway cat /data/http_auth.json
```

Задать свой пароль — впишите `MAXGW_HTTP_PASS=...` в `.env` и перезапустите: `docker compose up -d`.

1. В веб-интерфейсе создайте инстанс нужного типа (MAX или Telegram) и выберите его
2. Введите телефон аккаунта и нажмите «Запросить код» (для Telegram код придёт в приложение Telegram, не в SMS)
3. Введите код
4. Если аккаунт защищён облачным паролем (2FA) — введите его
5. Статус сменится на «подключено». Готово, повторный вход не нужен

Для Telegram есть и вход по QR: кнопка «Вход по QR (Telegram)», на телефоне Telegram -> Настройки -> Устройства -> Подключить устройство. Удобно подключать клиентов: они просто сканируют QR, никаких кодов передавать не нужно.

При первом входе с нового номера аккаунт MAX создастся автоматически с именем из `.env` (`MAXGW_REG_FIRST`, `MAXGW_REG_LAST`).

## Несколько аккаунтов

Один шлюз держит несколько аккаунтов MAX и Telegram. Каждый аккаунт — «инстанс» со своим именем, типом, своей сессией, своим API-ключом и своим вебхуком. Первый инстанс создаётся автоматически с именем `default`.

Добавить аккаунт:

- через веб-интерфейс (имя + тип MAX/Telegram внизу списка аккаунтов), или
- через API:

```bash
curl -X POST http://127.0.0.1:8090/admin/instances \
  -H "X-Api-Key: АДМИН-КЛЮЧ" -H "Content-Type: application/json" \
  -d '{"name": "salon1"}'          # MAX (по умолчанию)
# или
  -d '{"name": "tg1", "type": "telegram"}'   # Telegram
```

В ответе придёт персональный API-ключ инстанса. Дальше входите в аккаунт так же, как описано выше (в веб-интерфейсе выбираете инстанс, или `POST /i/salon1/login`).

Ключи и уровни доступа:

- **Админ-ключ** (`MAXGW_API_KEY` в `.env`): управление инстансами, доступ ко всем операциям
- **Ключ инстанса**: только операции своего аккаунта (статус, код, отправка, журнал)

Смена аккаунта у инстанса: введите другой телефон в том же инстансе, старая сессия удалится автоматически. Отдельный вебхук для инстанса: `POST /admin/instances/{имя}/webhook {"url": "..."}`.

## Telegram-инстансы

Telegram-инстансы работают через MTProto (Telethon) от имени личного аккаунта. Что нужно:

1. Один раз получить api_id/api_hash на https://my.telegram.org/apps (войдите своим номером, создайте приложение, скопируйте два значения)
2. Вписать их в `.env`:

```
TG_API_ID=123456
TG_API_HASH=0123456789abcdef0123456789abcdef
```

3. Пересоздать контейнер: `docker compose up -d --build`

Дальше создайте инстанс с `type: telegram` (в веб-интерфейсе или через API) и войдите:

- по телефону: `POST /i/tg1/login {"phone": "+7..."}` — код придёт в приложение Telegram (внутри приложения, служебный чат Telegram), затем `POST /i/tg1/code {"code": "12345"}`
- или по QR: `POST /i/tg1/qr`, затем открывайте `GET /i/tg1/qr.png` (картинка обновляется автоматически каждые ~45 секунд) и отсканируйте в телефоне: Telegram -> Настройки -> Устройства -> Подключить устройство

Входящие уходят вебхуком в том же формате Green-API, что и у MAX, но с `typeInstance: "telegram"`. Идентификаторы: в личных чатах `chatId` = id пользователя Telegram (положительное число), у групп и каналов — отрицательные (`-100...`). По `chatId` из вебхука можно отвечать через `sendText`.

Скачивание вложений (фото, документы, голосовые):

```
GET /i/tg1/getFile?chat_id=123456&message_id=812
```

Вернёт сам файл (Content-Disposition с исходным именем). message_id приходит в вебхуке как `idMessage`, chat_id — как `senderData.chatId`.

Ограничения Telegram: за автоматизацию личного аккаунта Telegram может заблокировать (спам первым сообщениям новым людям). Пишите только тем, кто писал вам, или клиентам, которые оставили номер.

## VK-инстансы (личные страницы)

Личная страница ВК как инстанс шлюза. Работает через web_token залогиненного браузера: шлюз держит собственный headless Chromium с персистентным профилем на инстанс (`/data/vk_profiles/`), все запросы идут с IP сервера (токен привязан к IP). Официального API личных сообщений у ВК нет — путь неофициальный, темпы сами ограничиваем (отправка не чаще ~1 сообщения в 5-8 сек).

Создание и вход:

```bash
curl -u admin:$PASS -X POST http://127.0.0.1:8090/admin/instances \
  -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"name":"vkmain","type":"vk"}'

# Вход по QR (рекомендуется): откройте qr.png и отсканируйте приложением ВК
# (Профиль -> Настройки -> Вход по QR). Пароль и код не нужны.
curl -u admin:$PASS -X POST http://127.0.0.1:8090/i/vkmain/qr -H "X-Api-Key: $KEY"
curl -u admin:$PASS http://127.0.0.1:8090/i/vkmain/qr.png -H "X-Api-Key: $KEY" -o qr.png

# Либо вход по телефону: придёт код подтверждения (СМС/2FA)
curl -u admin:$PASS -X POST http://127.0.0.1:8090/i/vkmain/login \
  -H "X-Api-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"phone":"+7...","password":"пароль страницы"}'
curl -u admin:$PASS -X POST http://127.0.0.1:8090/i/vkmain/code \
  -H "X-Api-Key: $KEY" -H "Content-Type: application/json" -d '{"code":"1234"}'
```

После входа доступны те же операции, что у Telegram-инстансов:

```bash
POST /i/vkmain/sendText    {"chat_id": 123456789, "message": "..."}   # peer_id собеседника
GET  /i/vkmain/entity?query=durov   # id / короткий адрес / ссылка -> chatId
GET  /i/vkmain/dialogs     # список диалогов
GET  /i/vkmain/history?query=123456789&limit=20
```

Входящие уходят вебхуком в том же формате Green-API, `typeInstance: "vk"`: `senderData.chatId` = peer_id собеседника (личка), `textMessageData.textMessage` = текст.

Токен живёт недолго: шлюз сам перечитывает его из браузерного профиля (обычно без повторного кода). Если сессия истекла — `stage: expired`, повторите вход по QR.

Ограничения VK: метод неофициальный; за массовые первые сообщения страницу могут заблокировать. Держите темп низким (десятки сообщений в день), тексты уникальными, профиль «живым».

## Подключение к n8n

### Шлюз и n8n на одном сервере (общая docker-сеть)

Чтобы n8n звал шлюз по имени контейнера (`http://maxgateway:8090`), подключите его к docker-сети n8n через локальный файл `docker-compose.override.yml` (не коммитится, в `.gitignore`):

```yaml
services:
  maxgateway:
    networks:
      - n8n

networks:
  n8n:
    name: localai_default   # имя сети вашего n8n-стека: `docker network ls | grep -i n8n`
    external: true
```

Затем `docker compose up -d`. Если n8n на другом сервере — override не нужен, открывайте порт через reverse proxy и вызывайте по HTTPS.

### Входящие сообщения

В `.env` укажите адрес вебхука (общий для всех инстансов) или задайте отдельный вебхук каждому инстансу через API `POST /admin/instances/{имя}/webhook`:

```
MAXGW_WEBHOOK_URL=https://ваш-n8n/webhook/max_incoming
```

и перезапустите: `docker compose restart`. Каждое входящее сообщение уйдёт POST-запросом:

```json
{
  "typeWebhook": "incomingMessageReceived",
  "instanceData": { "idInstance": 1, "instanceName": "default", "wid": "+79990000000", "typeInstance": "max" },
  "timestamp": 1789743931,
  "idMessage": "117292658309101931",
  "senderData": {
    "chatId": "373749415",
    "senderId": "373749415",
    "senderName": "Иван"
  },
  "messageData": {
    "typeMessage": "textMessage",
    "textMessageData": { "textMessage": "Привет, хочу записаться" }
  }
}
```

В поле `instanceData.instanceName` приходит имя инстанса — по нему n8n маршрутизирует сообщение нужному салону. В `typeInstance` — тип (`max` / `telegram`).

Идентификаторы чатов (как в Green-API):

- личные чаты: `chatId` = id пользователя (peer user_id) — по нему можно отвечать, шлюз сам развернёт его во внутренний id чата
- дополнительно приходит `rawChatId` — внутренний id чата
- групповые чаты: `chatId` = id группы (у Telegram группы и каналы — отрицательные числа, `-100...`)

В n8n это принимает нода Webhook (POST, путь `max_incoming`).

### Голосовые сообщения

Если клиент прислал голосовое, шлюз скачает его и, если настроен STT, расшифрует в текст:

```json
{
  "messageData": {
    "typeMessage": "textMessage",
    "voiceMessageData": { "duration": 14, "transcript": "Здравствуйте, хочу записаться на маникюр" },
    "textMessageData": { "textMessage": "Здравствуйте, хочу записаться на маникюр" }
  }
}
```

Если расшифровка получилась, голосовое приходит как обычное `textMessage` (текст = расшифровка, исходные данные — в `voiceMessageData`). Бот в n8n обрабатывает голосовые как текстовые без доработок.

Настройка STT в `.env` (любой OpenAI-совместимый сервис):

```
STT_BASE_URL=https://api.openai.com/v1/audio/transcriptions
STT_API_KEY=sk-...
STT_MODEL=whisper-1
```

Без настроенного STT голосовые приходят с `typeMessage: "voiceMessage"` и `transcript: null` — без текста.

### Исходящие сообщения

Нода HTTP Request в n8n:

- Method: `POST`
- URL: `http://maxgateway:8090/i/ИМЯ-ИНСТАНСА/sendText` (если n8n и шлюз в одной сети Docker) или `http://IP-СЕРВЕРА:8090/i/ИМЯ-ИНСТАНСА/sendText`
- Headers: `X-Api-Key` = ключ инстанса или админ-ключ
- Body (JSON):

```json
{ "phone": "+79990000000", "message": "Ваши ноготки ждут в пятницу в 15:00!" }
```

Вместо `phone` можно передать `chat_id` (число) из входящего вебхука: id пользователя для личных чатов или id группы. Для Telegram `chat_id` — это id из вебхука (у групп `-100...`).

## Справка API

Все запросы требуют заголовок `X-Api-Key` (админ-ключ или ключ инстанса, где указано).

Админ (только админ-ключ):

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/admin/overview` | Сводка по всем инстансам |
| POST | `/admin/instances` | `{"name": "salon1", "type": "max"|"telegram"}` — создать инстанс, вернёт его API-ключ |
| GET | `/admin/instances` | Список инстансов с ключами |
| POST | `/admin/instances/{имя}/webhook` | `{"url": "..."}` — вебхук инстанса |
| DELETE | `/admin/instances/{имя}` | Удалить инстанс и его сессию |

Инстанс (ключ инстанса или админ-ключ):

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/i/{имя}/status` | Статус сессии и соединения |
| POST | `/i/{имя}/login` | `{"phone": "+7..."}` — начать вход |
| POST | `/i/{имя}/code` | `{"code": "123456"}` — код из SMS (MAX) или из Telegram |
| POST | `/i/{имя}/password` | `{"password": "..."}` — облачный пароль 2FA |
| POST | `/i/{имя}/sendText` | `{"phone": "+7...", "message": "..."}` или `{"chat_id": 123, "message": "..."}` |
| POST | `/i/{имя}/reset` | Сбросить сессию (потребуется новый вход) |
| GET | `/i/{имя}/recent` | Последние 25 входящих сообщений |
| POST | `/i/{имя}/qr` | Telegram: начать вход по QR-коду |
| GET | `/i/{имя}/qr.png` | Telegram: текущий QR-код картинкой |
| GET | `/i/{имя}/getFile?chat_id=..&message_id=..` | Telegram: скачать вложение из сообщения |

Для инстанса `default` работают и короткие пути без `/i/default/` (`/status`, `/sendText` и т.д.) — совместимость с версией 0.1.

## Безопасность

- По умолчанию шлюз слушает только `127.0.0.1:8090` — снаружи не виден
- Для доступа снаружи поставьте реверс-прокси (Caddy, Nginx) с HTTPS и не публикуйте порт напрямую
- API-ключ генерируется при установке, хранится в `.env`, не передавайте его третьим лицам
- Файлы сессий лежат в `./data/sessions` — не публикуйте эту папку и делайте бэкап; доступ к файлу сессии = доступ к аккаунту
- TG_API_ID/TG_API_HASH — это данные приложения, а не аккаунта; не публикуйте их, но менять при утечке не нужно

## Обновление

```bash
cd ~/max-gateway
docker compose down
git pull
docker compose up -d --build
```

Сессия в `./data` сохранится, повторный вход не нужен.

## Ограничения текущей версии

- Отправка только текста; вложения во входящих MAX отображаются как метаданные
- Вложения Telegram скачиваются целиком через `getFile` (без стриминга и превью)
- Расшифровка голосовых требует внешнего STT-сервиса (в `.env`)
- Вход в MAX только по SMS-коду; QR-вход — только у Telegram-инстансов
